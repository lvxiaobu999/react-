# 06. 为什么列表渲染需要稳定的 `key`？为什么不推荐用数组下标？

> 所属主题：基础与组件 ｜ [← 返回目录](./README.md)

## 回答要点

`key` 帮助 React 在同一层级的更新中识别元素身份，从而正确匹配、复用或删除节点。若列表可插入、删除或重排，数组下标会随位置变化，可能让组件状态或 DOM 状态落到错误的数据项上。

应优先使用数据中稳定且唯一的 ID。

## 易错点 / 追问

静态、永不重排且没有局部状态的列表使用下标风险较低，但不能把它当作通用默认值。`key` 也不会作为普通 prop 自动传给子组件。

## 实战验证

可运行 Demo：[react-app/src/questions/06-list-key/Demo.tsx](../../../react-app/src/questions/06-list-key/Demo.tsx)。用每行非受控输入框演示：以 `key={index}` 删除表头项时输入内容会“串行”，以 `key={id}` 则不会。
