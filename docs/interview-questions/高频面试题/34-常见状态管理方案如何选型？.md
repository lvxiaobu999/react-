# 34. 常见状态管理方案如何选型？

> 所属主题：工程化与生态 ｜ [← 返回目录](./README.md)

## 回答要点

先分类再选型：**服务端状态**（缓存、重试、失效）交给 React Query/SWR 一类库；**URL 状态**（搜索词、分页、筛选）放路由参数；剩下的**客户端状态**从组件本地 `useState` 开始，不够再提升，仍不够再考虑全局方案。

- **Context**：低频全局数据（主题、locale、当前用户）；高频更新会放大重渲染范围。
- **Redux Toolkit**：大型团队需要可预测的单向数据流、中间件和时间旅行调试时；样板和心智成本最高。
- **Zustand/Jotai**：轻量 store 或原子化状态，选择器订阅粒度细、样板少，是中小型项目常见的默认项。

## 易错点 / 追问

“全局状态越多越好维护”是反模式；把状态放到真正需要它的最低位置，派生数据保持计算而非复制。
